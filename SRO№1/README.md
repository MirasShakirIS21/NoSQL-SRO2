# Реестр учебных проектов

Учебный проект по дисциплине «Проектирование и применение NoSQL-технологий».

**Вариант:** 7  
**Технологии:** Python, MongoDB, PyMongo.

## 1. Описание проекта

«Реестр учебных проектов» — консольное приложение для хранения и управления информацией об учебных проектах, пользователях и задачах.

Система позволяет создавать проекты и задачи, назначать исполнителей, изменять статусы задач, просматривать проекты и выполнять запросы к базе данных MongoDB.

## 2. Основные возможности

- Хранение пользователей, учебных проектов и задач.
- Создание пользователей, проектов и задач.
- Изменение статуса задачи.
- Удаление задач.
- Просмотр всех проектов.
- Поиск проектов по статусу.
- Получение участников проекта.
- Поиск задач по исполнителю.
- Получение задач конкретного проекта.
- Поиск незавершённых задач высокого приоритета.
- Поиск просроченных задач.
- Подсчёт количества задач по статусам с помощью агрегации MongoDB.
- Создание индексов для типовых запросов.

## 3. Используемые технологии

- **Python** — язык программирования.
- **MongoDB** — документоориентированная NoSQL-СУБД.
- **PyMongo** — библиотека для подключения Python к MongoDB.
- **Visual Studio Code** — среда разработки.

## 4. Структура базы данных

Используется база данных `student_project_registry`.

Она включает три коллекции:

| Коллекция | Назначение |
|---|---|
| `users` | Пользователи, их имена, email и роли |
| `projects` | Учебные проекты, руководители, участники и статусы |
| `tasks` | Задачи, проекты, исполнители, приоритеты и сроки |

Для связи документов используются идентификаторы MongoDB `ObjectId`.

## 5. Индексы

В проекте предусмотрены следующие индексы:

- `projects.status` — поиск проектов по статусу.
- `projects.owner_id` — поиск проектов руководителя.
- `users.email` — уникальный индекс электронной почты.
- `tasks.assignee_id` и `tasks.status` — поиск задач исполнителя по статусу.
- `tasks.project_id` и `tasks.status` — поиск задач проекта по статусу.
- `tasks.status` и `tasks.due_date` — выборка задач по статусу и сроку.

## 6. Требования

Перед запуском необходимо установить:

1. Python.
2. MongoDB Server либо настроить доступ к MongoDB Atlas.
3. Библиотеку PyMongo.

## 7. Установка и запуск

### Шаг 1. Откройте папку проекта

Откройте папку с исходным кодом в Visual Studio Code.

### Шаг 2. Установите PyMongo

Откройте терминал VS Code и выполните:

```bash
python -m pip install pymongo
```

### Шаг 3. Запустите MongoDB

Для локального подключения сервер MongoDB должен быть установлен и запущен.

В текущей конфигурации используется адрес:

```text
mongodb://localhost:27017
```

При использовании MongoDB Atlas необходимо заменить адрес подключения в исходном коде на строку подключения своего кластера.

### Шаг 4. Запустите приложение

Перейдите в папку проекта и выполните:

```bash
python main.py
```

При успешном подключении приложение должно создать необходимые индексы, выполнить предусмотренную инициализацию данных и показать консольное меню.

Если появляется ошибка подключения, проверьте, запущен ли сервер MongoDB и соответствует ли адрес подключения настройкам сервера.

## 8. Демонстрационные данные

В программе предусмотрено заполнение базы синтетическими данными:

- 10 пользователей;
- 5 учебных проектов;
- 30 задач.

Инициализация выполняется функцией `seed_database(db)` при соблюдении условий, заданных в коде.

## 9. Примеры запросов

Приложение предусматривает следующие запросы:

1. Получение всех проектов.
2. Поиск активных проектов.
3. Получение участников проекта.
4. Получение задач конкретного исполнителя.
5. Получение задач проекта.
6. Поиск открытых задач высокого приоритета.
7. Поиск просроченных незавершённых задач.
8. Подсчёт задач по статусам проекта.

## 10. Проверка работы

Для проверки приложения рекомендуется выполнить следующие действия:

1. Убедиться, что MongoDB доступна.
2. Запустить `main.py`.
3. Проверить вывод списка проектов.
4. Выполнить поиск задач исполнителя.
5. Изменить статус тестовой задачи.
6. Проверить удаление тестовой задачи.
7. Выполнить агрегирующий запрос.

Фактические результаты тестирования следует зафиксировать после запуска программы.

## 11. Безопасность

Не размещайте пароли, секретные ключи и личные данные в открытом GitHub-репозитории.

Если используется MongoDB Atlas, храните строку подключения с учётными данными в переменных окружения или другом защищённом конфигурационном хранилище.

Текущая версия программы использует адрес подключения, заданный в исходном коде. Для чтения переменных окружения или файла `.env` необходимо отдельно реализовать соответствующую логику.

## 12. Ограничения

Проект является учебным прототипом. В нём не реализованы полноценная авторизация пользователей, разграничение прав доступа и графический интерфейс.

Автоматическое заполнение базы зависит от условий, реализованных в `seed_database(db)`. Для повторного и частичного заполнения данных логику инициализации можно усовершенствовать.
